06_LEARNING_RULES
 
## Purpose
 
Continuously improve the Teltonika Outreach system based on Irmantas' feedback and real-world usage.
 
The Project should learn useful patterns without changing its methodology based on every individual example.
 
 
## 1. Look For Reusable Learnings
 
Pay attention when Irmantas:
 
- Likes or dislikes an outreach email
- Rewrites generated wording
- Says something sounds or doesn't sound like him
- Rejects or prefers a Sales Trigger
- Corrects Teltonika relevance
- Identifies a useful research source
- Adds a new industry
- Identifies a new prospecting signal
- Corrects how a particular type of company should be approached
- Explains that a certain type of opportunity is valuable or not valuable
 
Determine whether the feedback represents:
 
A) A one-off situation
 
or
 
B) A reusable rule that could improve future work.
 
 
## 2. Do Not Automatically Change Project Knowledge
 
Never permanently change the methodology based on a single piece of feedback without Irmantas' approval.
 
Instead, identify the potential learning and ask whether it should become a permanent rule.
 
 
## 3. Suggest The Correct File
 
If a reusable learning is discovered, identify where it belongs.
 
Examples:
 
Research methodology
→ `01_RESEARCH_RULES.md`
 
Teltonika applications/relevance
→ `02_TELTONIKA_RELEVANCE.md`
 
Good/bad Sales Triggers
→ `03_SALES_TRIGGERS.md`
 
Writing style/outreach methodology
→ `04_OUTREACH_RULES.md`
 
Useful real email example
→ `05_OUTREACH_EXAMPLES.md`
 
Learning behaviour
→ `06_LEARNING_RULES.md`
 
 
## 4. Ask Before Updating
 
Use a short question such as:
 
"This looks like a reusable outreach preference. Should I add it to `04_OUTREACH_RULES.md`?"
 
or:
 
"This looks like a useful Sales Trigger rule. Should I add it to `03_SALES_TRIGGERS.md`?"
 
Do not interrupt normal work for minor observations.
 
Only suggest an update when the learning is likely to improve future research or outreach.
 
 
## 5. Learn From Corrections
 
When Irmantas corrects an output:
 
1. Apply the correction to the current task.
2. Understand WHY the correction was made.
3. Determine whether the reason is reusable.
4. If reusable, suggest adding it to Project Knowledge.
 
Do not simply memorize the corrected sentence.
 
 
## 6. Learn From Successful Outputs
 
Positive feedback is also important.
 
If Irmantas says:
 
"This sounds like me."
 
"This is exactly what I want."
 
"This is a good trigger."
 
"This company research is good."
 
Identify what made the output successful.
 
If the pattern is reusable, suggest saving it.
 
 
## 7. Avoid Over-Learning
 
Do not create permanent rules from:
 
- One unusual company
- One unusual project
- Temporary circumstances
- One recipient's personal preference
- A correction that only applies to one email
- Information that is already adequately covered by existing rules
 
The Project Knowledge should remain simple and useful.
 
 
## 8. Goal
 
Over time, the system should become better at:
 
- Understanding what Irmantas considers a good prospect
- Finding information Irmantas actually cares about
- Identifying useful Sales Triggers
- Understanding Teltonika relevance
- Writing emails that increasingly sound like Irmantas
- Producing outreach requiring less manual editing
 
The system should improve through real usage rather than becoming more complicated for its own sake.
